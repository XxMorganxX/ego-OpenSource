# PR Review: SKU migration

[[Sam Rivera]] opened a PR adding the unique constraint on (batch_id, sku) and backfilling historical rows. [[Avery Quinn]] approved after confirming the backfill runs read-only against production first.

## What the PR does

- Creates the normalized tables from the [[2026-01-10 schema decision|Fruit DB Schema Decision]].
- Adds a unique constraint on (batch_id, sku) so the same SKU cannot be loaded twice for one harvest batch.
- Backfills historical rows in two passes: a read-only dry run that reports conflicts, then the real write.

## Review notes

- Avery asked for the dry-run report to list every conflicting row so the warehouse team can check them by hand. Added.
- Sam wants to test against a full copy in staging before merging. Blocked until staging is provisioned, see [[2026-01-19 chat staging access|Chat: staging access blocked]].

## Update 2026-01-24

Merged and deployed after staging was unblocked. This is the fix for the duplicate SKU import problem. The constraint is what stopped the double-counting described in [[2026-01-22 dup sku bug|Bug: duplicate SKU on import]]: the import now rejects a repeated (batch_id, sku) pair instead of adding it again.
